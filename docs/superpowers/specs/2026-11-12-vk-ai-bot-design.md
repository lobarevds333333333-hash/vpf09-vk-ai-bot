# Дизайн: AI-бот в ВКонтакте — продвинутое задание VPf09

Дата: 2026-11-12
Курс: «Профессия вайб-кодер», модуль 7, урок «VPf09. Кейс 1: AI-бот в VK»
Вариант задания: 2 (продвинутый — под свою задачу)

## 1. Зачем

Собрать AI-бота ВКонтакте по спецификации урока и выполнить продвинутую часть:

- **новый режим общения** — «Ментор по Python» (6-й, сверх 5 базовых);
- **одна продвинутая фича** — «Долгосрочные факты о пользователе»;
- база собирается **с нуля** по промпту урока (не расширение VPi03);
- провайдер LLM — **OpenRouter** вместо ProxyAPI (решение заказчика);
- подготовить материалы для сдачи: код, README, описание изменений.

## 2. Цели

1. Работающий бот на VKBottle + LongPoll API, отвечающий на сообщения.
2. Многодиалоговый режим: создание, переименование, удаление, переключение диалогов.
3. 6 режимов общения, каждый — отдельный system prompt; режим привязан к диалогу.
4. Краткосрочная память: до 100 последних сообщений активного диалога.
5. Долгосрочные факты: сохраняются в JSON пользователя, переживают перезапуск и
   подмешиваются в system prompt любого диалога/режима.
6. Клавиатуры ВК: главное меню, список диалогов, режимы, настройки, факты.
7. Асинхронность, статус «печатает…», обработка ошибок API, fallback-ответ.

## 3. Не-цели (что сознательно не делаем)

- Никаких БД (SQLite/PostgreSQL) — ограничение урока: только JSON.
- Никакого Callback API и вебхуков — только LongPoll (локальный запуск).
- Никакого автоматического извлечения фактов моделью — только явная команда
  «Запомни: …» (детерминированно и проверяемо).
- Нет деплоя на сервер, нет групповых чатов, нет админ-панели.
- Нет поддержки Markdown в ответах (ВК его не рендерит).

## 4. Анти-цели (считаем провалом, даже если код «работает»)

- Факты исчезают после перезапуска бота.
- Смена режима/диалога теряет или смешивает историю.
- Секреты (VK_TOKEN, OPENROUTER_API_KEY) попадают в репозиторий.
- Бот падает/молчит при ошибке LLM API.
- Дублирование ответов из-за двух запущенных процессов (проверка на тесте).

## 5. Ограничения и допущения

- Python 3.11, зависимости: `vkbottle>=4.10`, `python-dotenv`, `openai>=1.40`
  (AsyncOpenAI), `aiohttp`, `pydantic` (только для моделей, если понадобится).
- OpenRouter: `base_url=https://openrouter.ai/api/v1`. С российского IP отдаёт
  **403 (гео-блок)** — живой тест только с включённым VPN.
- Модель по умолчанию: `google/gemini-2.5-flash-lite` (меняется одной env-строкой).
- Лимиты: сообщение ≤ 4000 символов, история ≤ 100 сообщений, факты ≤ 20 шт.
- Данные: `users/<user_id>.json`, атомарная запись (tmp + replace).
- Секреты только в `.env` (в `.gitignore`), `.env.example` — без значений.
- Токен ВК и ключ OpenRouter переиспользуются из `VPi03/.env` (копируются без вывода
  значений); при необходимости заказчик заменит их.

## 6. Архитектура

```
main.py                      — точка входа: сборка Bot, загрузка labeler, run()
config/settings.py           — env через dotenv, валидация, лимиты, режимы (id → prompt)
models/entities.py           — Message, Dialog, UserProfile (dataclasses + to_dict/from_dict)
storage/user_store.py        — JSON-репозиторий: load/save/atomic, ensure_user
services/ai_service.py       — OpenRouter AsyncOpenAI, сборка контекста, fallback
services/dialog_service.py   — CRUD диалогов, активный диалог, смена режима, очистка
services/facts_service.py    — добавить/список/очистить факты, вставка в prompt
keyboards/menus.py           — клавиатуры: главное меню, диалоги, режимы, настройки, факты
bot/handlers.py              — обработчики сообщений и кнопок (LongPoll)
utils/typing.py              — messages.setActivity (typing) на время генерации
tests/test_smoke.py          — хранилище, лимит истории, факты, контекст (без сети)
users/                       — runtime JSON (gitignored)
```

### Поток обработки сообщения

```
VK LongPoll → handler текста
  → user_store.ensure_user(user_id)
  → dialog = активный диалог
  → facts = user.facts
  → ai_service.ask(mode_prompt, facts, messages[-100:], user_text)
       ├─ setActivity(typing)
       ├─ AsyncOpenAI.chat.completions.create(model=env, messages=[system]+history+user)
       └─ ошибка → fallback-текст
  → dialog.messages.append(user), append(assistant), cap 100
  → user_store.save(user)
  → api.messages.send(text)
```

### Модель данных (users/<id>.json)

```json
{
  "user_id": 123456,
  "active_dialog_id": "main",
  "facts": ["меня зовут Вал", "учусь на вайб-кодера"],
  "dialogs": [
    {
      "id": "main",
      "title": "Основной",
      "mode_id": "assistant",
      "messages": [
        {"role": "user", "content": "привет", "timestamp": "2026-11-12T12:00:00"}
      ]
    }
  ]
}
```

### Режимы (id → system prompt)

| id | Название | Примечание |
|---|---|---|
| assistant | Обычный помощник | базовый |
| programmer | Программист | базовый |
| teacher | Преподаватель | базовый |
| business | Бизнес-консультант | базовый |
| friend | Дружелюбный собеседник | базовый |
| **python_mentor** | **Ментор по Python** | **новый режим задания**: пошаговое обучение, разбор кода, простые примеры, проверка понимания вопросами |

Все промпты: русский язык, без Markdown, ответы ≤ 1500 токенов.

### Долгосрочные факты (продвинутая фича)

- Команда в любом диалоге: `Запомни: <текст>` → факт добавляется (лимит 20,
  обрезка до 200 символов, дубликаты игнорируются).
- Кнопка «🧠 Факты обо мне» → список фактов + кнопка «Очистить факты».
- Факты вставляются в system prompt **всех** диалогов:
  `Известные факты о пользователе: - … - …`.
- Хранение — в JSON пользователя, отдельно от истории диалогов.

### Клавиатуры и сценарии

- **Главное меню** (inline): 🆕 Новый диалог · 📋 Мои диалоги · 🎭 Сменить режим ·
  🧠 Факты обо мне · ⚙️ Настройки · ❓ Помощь.
- **Мои диалоги**: список кнопок-переключателей + «Переименовать» / «Удалить» /
  «🆕 Новый». Последний диалог удалить нельзя (уведомление).
- **Переименование**: FSM-состояние ожидания нового названия (отмена — «Отмена»).
- **Сменить режим**: 6 кнопок; применяется к активному диалогу.
- **Настройки**: текущая модель, текущий режим, «Очистить историю».
- Любой обычный текст (не команда) → запрос к LLM в активном диалоге.

## 7. Обработка ошибок

- Пустое/слишком длинное (>4000) сообщение → вежливый отказ без вызова LLM.
- Ошибка сети/API → лог + fallback-сообщение, история не ломается.
- Нет ключей в env → бот не стартует с понятным сообщением в лог.
- Битый JSON пользователя → пересоздание профиля с записью в лог (данные не теряем
  молча: файл переименовывается в `.bak`).

## 8. Тестирование

- **Smoke (без сети)**: roundtrip хранилища, cap 100 сообщений, лимит/дедуп фактов,
  вставка фактов в system prompt, наличие 6 режимов, fallback при исключении.
- **Живой AI**: один запрос к OpenRouter (после включения VPN) — ответ непустой.
- **Ручной чек-лист ВК** (совпадает со скриншотами для сдачи): главное меню →
  новый диалог → смена режима на «Ментор по Python» → ответ → «Запомни: …» →
  новый диалог → бот помнит факт.

## 9. Риски

| Риск | Митигация |
|---|---|
| OpenRouter 403 без VPN | тест после включения VPN; код не зависит от сети при smoke-тестах |
| Конфликт с запущенным ботом VPi03 (тот же токен) | перед запуском проверить процессы Python |
| Markdown в ответах | запрет в system prompt |
| Дубли ответов | один процесс; проверка диспетчером задач |

## 10. Мои решения (builder's calls)

- Модель по умолчанию — `google/gemini-2.5-flash-lite`: дешёвая, быстрая, хорошо
  следует system prompt; меняется через `OPENROUTER_MODEL`.
- Факты — список строк, без пар ключ-значение: проще и достаточно для кейса.
- Переименование диалога — через FSM-состояние (без ввода названия в кнопке).
- Хранилище — атомарная запись через временный файл + `os.replace`.
- Тесты — `unittest` (стандартная библиотека), без новых зависимостей.
